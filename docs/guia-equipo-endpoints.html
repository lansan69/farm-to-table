01

Cómo probar los endpoints

Antes de conectar el backend a tus pantallas, lo más importante es verificar que cada endpoint devuelve exactamente lo que esperas. Tienes tres formas de hacerlo — elige la que más te acomode.

✓ La URL base de todos los endpoints es: http://localhost/dashboard/farm-to-table/src/api/ — guárdatela, la usarás en todos los ejemplos.

Opción A — Directo en el navegador (solo GET)

Para consultas de solo lectura, puedes pegar la URL directo en la barra del navegador y ver la respuesta JSON. Es la forma más rápida para verificar que un endpoint existe y responde.

URL # Pega cualquiera de estas en Chrome, Firefox o Edge: http://localhost/dashboard/farm-to-table/src/api/marketplace.php http://localhost/dashboard/farm-to-table/src/api/marketplace.php?id=1 http://localhost/dashboard/farm-to-table/src/api/marketplace.php?categorias=1 http://localhost/dashboard/farm-to-table/src/api/catalogo.php?q=tomate http://localhost/dashboard/farm-to-table/src/api/auth.php?zonas=1
⚠ El navegador solo sirve para peticiones GET. Para POST, PUT y PATCH necesitas Postman o curl.

Opción B — Postman (recomendado)

Postman te permite probar cualquier tipo de petición (GET, POST, PATCH, PUT) y ver la respuesta con formato. Si no lo tienes instalado, descárgalo en postman.com — es gratis.

  1. Abre Postman y crea una nueva Collection llamada "Farm to Table"
  2. Dentro de la colección, ve a Variables y agrega: base = http://localhost/dashboard/farm-to-table/src/api
  3. Crea una nueva petición. En la URL escribe {{base}}/marketplace.php
  4. Selecciona el método (GET, POST, etc.) y presiona Send
  5. La respuesta aparece abajo en formato JSON — verifica que "status" sea "ok"

Para peticiones POST, PUT y PATCH, ve a la pestaña Body, selecciona raw y elige JSON en el menú desplegable antes de escribir el cuerpo.

JSON — Body de ejemplo para login { "action": "login", "identificador": "5512345678", "contrasena": "mipassword" }

La respuesta siempre tiene la misma forma:

JSON — Respuesta exitosa { "status": "ok", "data": { ... los datos que pediste ... } } // Si hay un error: { "status": "error", "message": "Descripción del problema" }

Opción C — curl en la terminal

Si prefieres trabajar desde la terminal, curl hace lo mismo que Postman pero en línea de comandos.

BASH # GET — listar lotes disponibles curl "http://localhost/dashboard/farm-to-table/src/api/marketplace.php" # GET con parámetros — buscar por nombre curl "http://localhost/dashboard/farm-to-table/src/api/marketplace.php?nombre=tomate" # POST — login curl -X POST \ -H "Content-Type: application/json" \ -d '{"action":"login","identificador":"5512345678","contrasena":"mipass"}' \ "http://localhost/dashboard/farm-to-table/src/api/auth.php" # PATCH — cambiar estado de un lote curl -X PATCH \ -H "Content-Type: application/json" \ -d '{"id_lote":1,"id_productor":3,"estado":"en_negociacion"}' \ "http://localhost/dashboard/farm-to-table/src/api/lotes.php"
✓ Si la respuesta muestra "status":"error" con el mensaje "Error de conexión a la base de datos", el problema no es el endpoint sino que la BD no está configurada. Verifica config/config.php.
02

Estructura de archivos del backend

El backend se divide en tres capas. Cada capa tiene una sola responsabilidad. Si necesitas modificar algo, aquí encuentras dónde está:

src/ │ ├── core/ ← utilidades compartidas │ ├── Response.php ← genera json_ok() y json_error() │ ├── Router.php ← lee método HTTP, body y parámetros │ └── Database.php ← conexión a la base de datos (PDO) │ ├── api/ ← los endpoints que probamos en Postman │ ├── auth.php ← login y registro │ ├── marketplace.php ← explorar lotes disponibles │ ├── favoritos.php ← lista y toggle de favoritos │ ├── lotes.php ← panel del productor │ ├── negociaciones.php ← contraofertas comprador ↔ productor │ ├── entregas.php ← seguimiento de entrega y QR │ ├── perfil.php ← perfil y calificaciones │ └── catalogo.php ← productos y categorías (formularios) │ ├── domain/ ← lógica de negocio, llamada desde api/ │ ├── AuthDomain.php │ ├── MarketplaceDomain.php │ ├── LoteDomain.php │ ├── NegociacionDomain.php │ ├── EntregaDomain.php │ └── PerfilDomain.php │ └── models/ ← consultas SQL, llamadas desde domain/ ├── UsuarioModel.php ├── LoteExcedenteModel.php ├── NegociacionModel.php └── ... (uno por tabla)

El flujo de una petición siempre sigue el mismo camino de izquierda a derecha:

Postman / JS
→
api/*.php
→
domain/*.php
→
models/*.php
→
Base de datos
→
JSON
⚠ Si necesitas cambiar qué datos devuelve un endpoint, el lugar correcto es el modelo correspondiente en src/models/, no el archivo de api/. Los archivos de api/ solo reciben y delegan.
03

Endpoints disponibles y parámetros

Todos los parámetros marcados con requerido deben incluirse siempre. Los marcados con opcional pueden omitirse.

auth.php — Acceso y registro

GET /auth.php?zonas=1 Lista de zonas activas para el formulario de registro
# Sin body. Devuelve un arreglo de zonas con id_zona, nombre_delegacion y codigo_postal.
POST /auth.php — action: "login" Inicia sesión con teléfono o email
{ "action": "login", "identificador": "5512345678" requerido ← teléfono o email "contrasena": "mipassword" requerido }
POST /auth.php — action: "register" Registra un nuevo usuario
{ "action": "register", "id_zona": 1 requerido "nombre": "Juan García" requerido "rol": "productor" requerido ← productor | organizacion | admin "telefono": "5512345678" requerido "contrasena": "mipassword" requerido "email": "j@ejemplo.com" opcional }

marketplace.php — Explorar lotes

GET /marketplace.php Todos los lotes disponibles, con filtros opcionales
# Parámetros de query (todos opcionales): ?nombre=tomate opcional ← filtra por nombre del producto ?categoria=2 opcional ← filtra por id de categoría ?zona=1 opcional ← filtra por zona operativa # Sin parámetros devuelve todos los lotes disponibles.
GET /marketplace.php?id=N Detalle completo de un lote con sus fotos
?id=3 requerido ← id del lote
GET /marketplace.php?categorias=1 Lista de categorías para el selector de filtros
# Sin body adicional. Útil para poblar el dropdown de categorías.

favoritos.php — Productos favoritos

GET /favoritos.php?id_usuario=N Todos los lotes marcados como favoritos por el usuario
?id_usuario=5 requerido
POST /favoritos.php Agrega o quita un lote de favoritos (toggle automático)
{ "id_usuario": 5 requerido "id_lote": 12 requerido } # Devuelve { "action": "added" } o { "action": "removed" }

lotes.php — Panel del productor

GET /lotes.php?id_productor=N Lotes publicados por el productor (mis lotes)
?id_productor=3 requerido
GET /lotes.php?id_lote=N Detalle completo de un lote (datos + fotos + trazabilidad)
?id_lote=7 requerido
GET /lotes.php?urgentes=1 Lotes con 3 días o menos de vida útil restante
# Sin body adicional. Útil para mostrar alertas al usuario.
POST /lotes.php Publica un nuevo lote
{ "id_productor": 3 requerido "id_producto": 8 requerido "cantidad": 150.5 requerido ← en kilogramos "fecha_cosecha": "2026-05-28" requerido ← formato YYYY-MM-DD "precio": 12.00 requerido "fotos": ["https://..."] opcional ← arreglo de URLs }
PATCH /lotes.php Cambia el estado de un lote
{ "id_lote": 7 requerido "id_productor": 3 requerido ← debe ser el dueño del lote "estado": "en_negociacion" requerido ← ver estados abajo } # Estados válidos: disponible | en_negociacion | asignado | caducado

negociaciones.php — Contraofertas

GET /negociaciones.php Consultas de negociaciones — usar uno de los parámetros
?id_comprador=5 ← negociaciones activas del comprador ?id_productor=3 ← negociaciones activas del productor ?hilo=2 ← historial de ofertas de una negociación (el "chat") ?historial_comprador=5 ← todas las compras completadas del comprador ?historial_productor=3 ← todas las ventas completadas del productor
POST /negociaciones.php — action: "iniciar" El comprador abre la negociación con su primera oferta
{ "action": "iniciar", "id_lote": 7 requerido "id_comprador":5 requerido "monto": 10.50 requerido "comentario": "¿Puede bajar un poco?" opcional }
POST /negociaciones.php — action: "contraoferta" Cualquiera de las partes envía una nueva ronda
{ "action": "contraoferta", "id_negociacion": 2 requerido "id_emisor": 3 requerido ← quien envía la oferta "monto": 11.00 requerido "comentario": "Lo mejor que puedo dar." opcional }
PATCH /negociaciones.php Acepta o rechaza la negociación
{ "action": "aceptar" ← o "rechazar" "id_negociacion": 2 requerido } # Al aceptar, la BD crea la entrega logística automáticamente.

entregas.php — Seguimiento de entrega

GET /entregas.php Consultar una entrega — usar uno de los parámetros
?id_negociacion=2 ← entrega ligada a esa negociación ?qr=ABC123XYZ ← busca por código QR antes de confirmar
POST /entregas.php — action: "confirmar" El comprador confirma que recibió el pedido
{ "action": "confirmar", "codigo_qr": "ABC123XYZ" requerido }
PATCH /entregas.php — action: "estado" El productor actualiza el estado logístico
{ "action": "estado", "id_entrega": 4 requerido "estado": "en_transito" requerido } # Estados válidos: preparando_lote | en_transito | entregado | incidencia

perfil.php — Perfil y calificaciones

GET /perfil.php?id_usuario=N&rol=X Perfil completo con estadísticas y valoraciones
?id_usuario=5 requerido ?rol=comprador ← comprador (default) | productor
PUT /perfil.php Actualiza los datos editables del perfil
{ "id_usuario": 5 requerido "nombre": "Juan García" requerido "telefono": "5599887766" requerido "id_zona": 2 requerido }
POST /perfil.php — action: "valoracion" Registra una calificación al finalizar una entrega
{ "action": "valoracion", "id_entrega": 4 requerido "id_evaluador": 5 requerido ← quien califica "id_evaluado": 3 requerido ← quien es calificado "estrellas": 4 requerido ← número del 1 al 5 "comentarios": "Buen producto, puntual." opcional }

catalogo.php — Búsqueda de productos

GET /catalogo.php Catálogo completo, búsqueda o categorías según parámetro
# Sin parámetros → catálogo completo de productos ?q=tomate ← búsqueda por nombre parcial (para autocompletar) ?categorias=1 ← lista de categorías para selectores
04

Próximos pasos — conectar con las pantallas

Una vez que verificaste que los endpoints responden correctamente en Postman, el siguiente paso es consumirlos desde tus archivos .js dentro de cada pantalla. Así funciona la conexión completa:

Paso 1 — Usar http.js para hacer la petición

El proyecto incluye un módulo public/assets/js/http.js que envuelve fetch(). Tu .js de pantalla nunca debe llamar a fetch() directamente — siempre pasa por este módulo.

JS — En tu archivo de pantalla // marketplace.js import { Http } from '../../../../assets/js/http.js'; export async function init(container) { // Llama al endpoint y recibe los datos const lotes = await Http.get('marketplace.php'); // Inyecta los datos en el HTML const grid = container.querySelector('#productsGrid'); grid.innerHTML = lotes.map(lote => ` <article class="product-card"> <h3>${lote.nombre_producto}</h3> <p>${lote.precio_recuperacion_sugerido}</p> </article> `).join(''); }

Paso 3 — Qué hacer cuando la respuesta llega

La respuesta siempre llega dentro de data. Dependiendo del endpoint, data puede ser un objeto o un arreglo. Puedes verificarlo primero en Postman antes de escribir el código.

JS — Manejo de respuesta y errores export async function init(container) { try { const lotes = await Http.get('marketplace.php?categorias=1'); // lotes es directamente el arreglo — Http.js extrae data por ti renderCategorias(container, lotes); } catch (err) { // Muestra un mensaje amigable en la pantalla, no un alert() container.querySelector('#error-msg').textContent = 'No se pudo cargar la información. Intenta de nuevo.'; } }
✓ Flujo recomendado: prueba el endpoint en Postman → verifica los campos que devuelve → úsalos en tu HTML. Si el campo no está en la respuesta, no lo inventes — avísale a Alan para ver si hay que agregar una columna en el modelo.
⚠ No hardcodees datos en el HTML para simular la respuesta. Usa los datos reales del endpoint desde el primer momento — es más fácil detectar errores así que descubrir al final que los nombres de campos no coinciden.
✕ Si el endpoint devuelve "status":"error" con código 500, el problema está en la base de datos o en el servidor. No es tu código JS. Revisa que XAMPP esté corriendo y que config/config.php tenga las credenciales correctas.
