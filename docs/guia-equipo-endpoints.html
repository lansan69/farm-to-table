01

Cómo probar los endpoints

Antes de conectar el backend a tus pantallas, lo más importante es verificar que cada endpoint devuelve exactamente lo que esperas. Tienes tres formas de hacerlo — elige la que más te acomode.

✓ La URL base de todos los endpoints es: http://localhost/dashboard/farm-to-table/src/api/ — guárdatela, la usarás en todos los ejemplos.

Opción A — Directo en el navegador (solo GET)

Para consultas de solo lectura, puedes pegar la URL directo en la barra del navegador y ver la respuesta JSON. Es la forma más rápida para verificar que un endpoint existe y responde.

URL # Pega cualquiera de estas en Chrome, Firefox o Edge: http://localhost/dashboard/farm-to-table/src/api/marketplace.php http://localhost/dashboard/farm-to-table/src/api/marketplace.php?id=1 http://localhost/dashboard/farm-to-table/src/api/marketplace.php?categorias=1 http://localhost/dashboard/farm-to-table/src/api/catalogo.php?q=tomate http://localhost/dashboard/farm-to-table/src/api/auth.php?zonas=1
⚠ El navegador solo sirve para peticiones GET. Para POST, PUT y PATCH necesitas Postman o curl.

Opción B — Postman (recomendado)

Postman te permite probar cualquier tipo de petición (GET, POST, PATCH, PUT) y ver la respuesta con formato. Si no lo tienes instalado, descárgalo en postman.com — es gratis.

  1. Abre Postman y crea una nueva Collection llamada "Farm to Table"
  2. Dentro de la colección, ve a Variables y agrega: base = http://localhost/dashboard/farm-to-table/src/api
  3. Crea una nueva petición. En la URL escribe {{base}}/marketplace.php
  4. Selecciona el método (GET, POST, etc.) y presiona Send
  5. La respuesta aparece abajo en formato JSON — verifica que "status" sea "ok"

Para peticiones POST, PUT y PATCH, ve a la pestaña Body, selecciona raw y elige JSON en el menú desplegable antes de escribir el cuerpo.

JSON — Body de ejemplo para login { "action": "login", "identificador": "5512345678", "contrasena": "mipassword" }

La respuesta siempre tiene la misma forma:

JSON — Respuesta exitosa { "status": "ok", "data": { ... los datos que pediste ... } } // Si hay un error: { "status": "error", "message": "Descripción del problema" }

Opción C — curl en la terminal

Si prefieres trabajar desde la terminal, curl hace lo mismo que Postman pero en línea de comandos.

BASH # GET — listar lotes disponibles curl "http://localhost/dashboard/farm-to-table/src/api/marketplace.php" # GET con parámetros — buscar por nombre curl "http://localhost/dashboard/farm-to-table/src/api/marketplace.php?nombre=tomate" # POST — login curl -X POST \ -H "Content-Type: application/json" \ -d '{"action":"login","identificador":"5512345678","contrasena":"mipass"}' \ "http://localhost/dashboard/farm-to-table/src/api/auth.php" # PATCH — cambiar estado de un lote curl -X PATCH \ -H "Content-Type: application/json" \ -d '{"id_lote":1,"id_productor":3,"estado":"en_negociacion"}' \ "http://localhost/dashboard/farm-to-table/src/api/lotes.php"
✓ Si la respuesta muestra "status":"error" con el mensaje "Error de conexión a la base de datos", el problema no es el endpoint sino que la BD no está configurada. Verifica config/config.php.

Próximos pasos — conectar con las pantallas

Una vez que verificaste que los endpoints responden correctamente en Postman, el siguiente paso es consumirlos desde tus archivos .js dentro de cada pantalla.

Paso 1 — Usar http.js para hacer la petición

El proyecto incluye un módulo public/assets/js/http.js que envuelve fetch(). Tu .js de pantalla nunca debe llamar a fetch() directamente — siempre pasa por este módulo.

JS — En tu archivo de pantalla // marketplace.js import { Http } from '../../../../assets/js/http.js'; export async function init(container) { const lotes = await Http.get('marketplace.php'); const grid = container.querySelector('#productsGrid'); grid.innerHTML = lotes.map(lote => ` <article class="product-card"> <h3>${lote.nombre_producto}</h3> <p>${lote.precio_recuperacion_sugerido}</p> </article> `).join(''); }

Paso 3 — Qué hacer cuando la respuesta llega

JS — Manejo de respuesta y errores export async function init(container) { try { const lotes = await Http.get('marketplace.php?categorias=1'); renderCategorias(container, lotes); } catch (err) { container.querySelector('#error-msg').textContent = 'No se pudo cargar la información. Intenta de nuevo.'; } }
✓ Flujo recomendado: prueba el endpoint en Postman → verifica los campos que devuelve → úsalos en tu HTML. Si el campo no está en la respuesta, no lo inventes — avísale a Alan para ver si hay que agregar una columna en el modelo.
⚠ No hardcodees datos en el HTML para simular la respuesta. Usa los datos reales del endpoint desde el primer momento — es más fácil detectar errores así que descubrir al final que los nombres de campos no coinciden.
✕ Si el endpoint devuelve "status":"error" con código 500, el problema está en la base de datos o en el servidor. No es tu código JS. Revisa que XAMPP esté corriendo y que config/config.php tenga las credenciales correctas.
